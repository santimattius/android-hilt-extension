# Hilt Trace Spike (slice 0)

> **Note:** the throwaway `spike/` modules (`:spike`, `:spike:processor`, `:spike:lib`) were removed from the build once the plugin and the sample covered the same ground. Their sources remain in git history at commit `d478048` (path `spike/`); the `./gradlew :spike:...` commands below were run at that commit. The fixtures under `hilt-trace-gradle-plugin/src/test/resources/fixtures/` are unaffected.

Change: `hilt-trace-and-coroutines`. All evidence was produced with stable versions: AGP 9.5.0 (built-in Kotlin, metadata 2.4.0), Kotlin 2.4.21, KSP 2.3.13, Hilt/Dagger 2.60.1, androidx.tracing 2.0.5, Gradle 9.6.0, JDK 25 daemon. No kapt. The throwaway app lives in `spike/` (`:spike`, `:spike:processor`, `:spike:lib`) and is not release wiring.

## Additional findings (not [SPIKE] items)

- `androidx.tracing:tracing` has two generations on one coordinate. The spike runtime resolved 1.2.0 transitively; with `android.dependency.useConstraints=true` the androidTest classpath was pinned to `{strictly 1.2.0}` and 2.0.5 failed to resolve until it was declared in the main `implementation` configuration. The runtime module must declare 2.0.5 as `api`, which upgrades consumers from 1.x to 2.0.5 (slices 2 and 6, documented in docs).
- `tracing-wire` does not expose `tracing` on the compile classpath; `tracing` must be declared explicitly (relevant to the sample app, slice 10).
- A `connectedDebugAndroidTest` run whose instrumentation process crashed (missing `androidx.test:runner`) reported Gradle exit status 0, while the XML result held a `testRunFailed` failure. Read the XML, not only the exit status.
- Hilt 2.60.1 plugin and our future factory share the same `transformDebugClassesWithAsm` task. `MainActivity` extends `Hilt_MainActivity` only after that transform (`MainActivity.before-hilt-transform` vs `.after-hilt-transform`).
- Not covered by this slice: reading Dagger metadata directly (design mentions it; no [SPIKE] item depends on it).

## Fixtures

Location: `hilt-trace-gradle-plugin/src/test/resources/fixtures/`. The readable bytecode of any class is regenerated with `javap -c -p -constants <file>.class`; that text is not checked in. Component classes are the pre-transform output of `hiltJavaCompileDebug` and carry the prefix `DaggerSpikeApp_HiltComponents_SingletonC$` inside their internal names; file names drop that prefix.

| Fixture | Covers |
|---|---|
| `SingletonCImpl$SwitchingProvider` | more than 100 bindings (`get0`, `get1`, router), scoped, unscoped via `Provider<T>`, `@Provides` scoped and unscoped, large constructor case |
| `SingletonCImpl` | accessors: inline, `Provider` backed, `@Binds`, multibinding, field-injected helper, `@EntryPoint` methods, `injectSpikeApp` |
| `ActivityCImpl`, `ActivityCImpl$SwitchingProvider`, `ActivityCImpl$SwitchingProvider$1` | `@AndroidEntryPoint` inject shape, `@AssistedInject` factory case |
| `ViewModelCImpl$SwitchingProvider` | `@HiltViewModel` case |
| `ActivityRetainedCImpl$SwitchingProvider` | small `get()` with `lookupswitch` and a static factory call |
| `MainActivity_MembersInjector`, `FieldInjected_MembersInjector`, `FieldInjected_Factory` | `injectX` statics and the `injectMembers` bridge |
| `Hilt_MainActivity`, `MainActivity.before-hilt-transform`, `MainActivity.after-hilt-transform` | `Hilt_*` generated base and the superclass rewrite |

Regenerate by running `./gradlew :spike:assembleDebug` and copying the classes named above from `spike/build/intermediates/classes/debug/hiltJavaCompileDebug/spike/`, `.../javac/debug/compileDebugJavaWithJavac/classes/spike/` and `.../built_in_kotlinc/debug/compileDebugKotlin/classes/spike/`.
